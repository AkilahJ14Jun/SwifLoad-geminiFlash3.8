 Here is the step-by-step implementation plan for deploying SwifLoad to Azure with a unified real-time database and
  downloadable mobile apps.
  ──────
  ### Phase 1: Architecture & Azure Infrastructure Planning

  1. Azure Cloud Hosting Selection
      • Service: Azure App Service (Linux, Node.js 20 LTS) or Azure Container Apps for full Next.js 14 server & API
      route support.
      • Target Region: South India / Central India (for lowest latency to Coimbatore operations).
      • Account: Authenticate via Azure CLI with akilahj@adwayit.com.
  2. Central Database & Real-Time Sync Engine
      • Database: Azure Cosmos DB (PostgreSQL / NoSQL) or Azure Database for PostgreSQL Flexible Server to replace
      client-side localStorage.
      • Real-Time Push: Server-Sent Events (SSE) / WebSockets (via Azure Web PubSub or Socket.io) to instantly sync
      trip status, driver assignments, and wallet transactions across Customer, Driver, and Admin portals.
  3. Mobile Delivery Strategy
      • Direct APK Downloads: Capacitor Android build generating standalone release APKs (SwifLoad-Customer.apk and
      SwifLoad-Driver.apk).
      • PWA (Progressive Web App): Installable web manifests for instant 1-tap installation on Android & iOS directly
      from browser.
      • Public Download Portal: Direct download links and QR codes hosted directly on the SwifLoad website.

  ──────
  ### Phase 2: Database Schema & API Layer Migration
                 , 1.3k tokens
  1. Data Model Migration (from LogisticsContext.tsx localStorage to DB)
      • Create models for:
          • trips (id, pickup, drop, vehicleCategory, status, otp, customer, driverId, pricing, timestamps).
          • drivers (id, name, phone, vehicle, status, onlineState, walletBalance, kycStatus).
          • customers (id, name, phone, customerType, walletBalance).
          • pricing_slabs, driver_groups, and referrals.

  2. Next.js API Route Endpoints (/api/...)
      • /api/trips: Create booking, list active trips, assign driver, update trip status.
      • /api/drivers: Driver registration, status toggle (online/offline), location ping.
      • /api/wallets: Credit, debit, top-up transactions.
      • /api/realtime: Event stream (SSE / WebSocket) delivering broadcast updates on any DB write.
  3. **Refactor LogisticsContext.tsx**
      • Replace localStorage.getItem/setItem with API calls and a real-time event listener so any trip state change
      immediately updates React state on all connected clients.

  ──────
  ### Phase 3: Route Architecture & Mobile Portal Separation

  1. Dedicated Role URL Routes
      • Currently all views run in a single simulator on /.
      • Add discrete routes for clean mobile and desktop separation:
          • /customer (Customer Mobile Web & App entry point)
          • /driver (Driver Mobile Web & App entry point)
          • /admin (Operations Admin Dashboard)
          • /downloads (Public page with APK download buttons & QR codes)

  2. Mobile Deep-Linking & Config
      • Configure capacitor.config.ts for Customer and Driver packages.

  ──────
  ### Phase 4: Cloud Provisioning & Deployment to Azure

  1. Azure CLI Setup & Resource Provisioning
      • Run az login to sign in as akilahj@adwayit.com.
      • Create Resource Group: rg-swifload-prod.
      • Provision Azure App Service Plan (B1 or P1v3) and App Service (swifload-app).
      • Provision Database (e.g., Azure Cosmos DB / PostgreSQL Flexible Server).
  2. Environment Configuration
      • Set up Azure App Settings for DB connection string, auth secrets, and base URL.
  3. Deployment Pipeline
      • Build production bundle (npm run build).
      • Deploy using Azure CLI (az webapp up) or GitHub Actions automated CI/CD workflow.
      • Verify cloud URL (HTTPS SSL active).

  ──────
  ### Phase 5: Mobile App Generation & Distribution

  1. Build Android APKs
      • Generate release Android packages using Capacitor CLI and Android Studio / Gradle.
      • Output signed .apk binaries for Customer App and Driver App.
  2. PWA Offline & Install Support
      • Generate manifest.webmanifest and service worker for instant "Add to Home Screen" on both Android & iOS.
  3. Host Downloadable APKs on Cloud
      • Place compiled APKs in /public/downloads/ or Azure Blob Storage.
      • Add a download banner on the landing page allowing users to download .apk or install PWA.

  ──────
  ### Phase 6: Multi-Device Real-Time Verification

  1. Multi-Role Live Test Matrix:
      • Device 1 (Customer App / Mobile): Place booking from Gandhipuram to Peelamedu.
      • Device 2 (Driver App / Mobile): Receive incoming dispatch popup in real-time without refreshing; accept trip;
      advance OTP status.
      • Device 3 (Admin Portal / Desktop): Monitor live map and status transition immediately reflecting changes.
  2. Final Build & Changelog Audit:
      • Run npm run build to confirm 0 compilation errors.
      • Update SESSION_CHANGELOG.md.
